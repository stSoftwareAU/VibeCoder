## PR Raising Requirements
When creating the PR, include the following based on the type of change:
- **UI Changes**: You MUST use Playwright MCP to generate screenshots as evidence. This includes ANY change that affects visual output: HTML reports, charts, CSS, formatting, layout, colours, fonts, buttons, modals, or any rendered content. Use `browser_navigate` to open a relevant URL, then use `browser_take_screenshot` to capture the result. Save screenshots to the `docs/evidence/` directory. Reference screenshots in your PR summary using markdown: `![Description](docs/evidence/filename.png)`. The worker will automatically process these screenshots. Do NOT claim you cannot generate screenshots — Playwright MCP is available and configured for headless browser automation. Do NOT describe visual changes in words only — you MUST capture an actual screenshot.
- **Performance Changes**: Include benchmark results showing before/after measurements to prove meaningful performance improvement. If no measurable improvement can be demonstrated, document this in the PR.
- **Bugs/Enhancements**: Follow TDD and ensure tests verify the result/outcome, not the implementation method. Tests should continue to work when the implementation is improved or refactored.

## Screenshot Generation with Playwright MCP
You have access to Playwright MCP for browser-based screenshot generation. To capture evidence:
1. Use `browser_navigate` to open a URL (e.g., a local dev server, a GitHub page, or any relevant web page).
2. Use `browser_snapshot` to inspect page structure if needed.
3. Use `browser_take_screenshot` to capture the screenshot, saving it to `docs/evidence/`.
4. Reference the screenshot in your PR summary: `![Description](docs/evidence/filename.png)`.

**IMPORTANT**: If your changes affect any visual output (HTML, charts, CSS, formatting, rendered reports), you MUST generate a screenshot. For example, if you modify an HTML report generator, open the generated report in the browser and screenshot it. Describing visual changes in words alone is NOT sufficient evidence.

If the change is purely backend/CLI with no web interface to screenshot, state this briefly in the evidence section and explain what was tested instead (e.g., test results, command output).
