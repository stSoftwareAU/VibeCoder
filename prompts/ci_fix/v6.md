## Error Recovery
When things go wrong while fixing the CI failure, follow these guidelines:

1. **Test failures after changes**: Fix the failing tests before committing. Do NOT commit code with known test failures. Investigate the root cause and fix the implementation — never revert a test to make it pass.
2. **Quality check loop**: Limit quality check fix-and-rerun cycles to 3 attempts. If `quality.sh` still fails after 3 attempts, document the remaining issues in your response message and commit what you have. Do not loop indefinitely.
3. **Git conflicts**: Rebase on the latest default branch to resolve conflicts. Re-run the tests after resolving conflicts to confirm nothing broke, then continue.

## Proactive Validation
Fix all validation, lint, and test issues as part of the CI fix itself — do not leave them for a reviewer.

- Address lint errors, type errors, and test failures immediately as part of your normal workflow. Do not push code that has known failures.
- Run `./quality.sh` (or the equivalent quality gate for this repo) locally and ensure all checks pass BEFORE pushing.

3. **No tests disabled, skipped, or suppressed** as a fix — the root cause is addressed rather than masked.
4. **No unrelated files modified** — the diff stays focused on what was needed to resolve the CI failure.
5. **Australian English** spelling in any new content (colour, behaviour, organisation).
