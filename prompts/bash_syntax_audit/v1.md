# Bash Syntax Audit (v1)

Verify that this repository's **own CI** blocks any pull request whose scripts
fail a basic-validity gate, and file one issue per missing gate. Bash has no
compile step, so an invalid bash script can regress into a repository with no
quality gate catching it — the exact FLEET regression that motivated this audit
(parent). Use Australian English (behaviour, colour, organisation,
analyse) in all human-readable output.

This audit is **deterministic and native** — two dedicated Deno detectors
perform the detection; no LLM judgement is involved in the core checks. It is
also **issue-only**: the deliverable is a set of GitHub findings issues. The
audit **never** opens a pull request or edits a file — each repository owns and
commits its own gate, and that fix rides a normal `work-on` pipeline PR later.
Repositories are **absolutely isolated**: this audit only verifies the presence
of a gate and raises an issue where one is missing.

## What the detectors check

- **Bash CI gate** (`worker/deno/lib/bash_ci_gate_scanner.ts`). Discovers the
  repo's bash scripts (`*.sh` / `*.bash` and bash-shebang files) and checks
  `.github/workflows/*` for two independent gates:
  1. a `bash -n` / `sh -n` **syntax** check, and
  2. a `shellcheck` **lint** check.

  A step that runs a committed gate script (e.g. `./quality.sh`,
  `quality/bash_syntax.sh`) counts as the gate — the script's committed
  contents are inspected. A repo with **no** bash scripts is *not applicable*
  (no finding); a repo with **no** loaded workflows leaves the gate *unknown*
  (no false "missing" finding).
- **Language-validity gate** (`worker/deno/lib/language_validity_gate.ts`). For
  each other main language (Rust, TypeScript, React, Java, Python) checks that a
  native basic-validity step is wired into CI — `cargo check`, `deno check` /
  `tsc --noEmit`, `mvn compile` / `gradle compileJava`, `python -m py_compile`.
  Basic validity only (does it compile / parse), not style or lint.

## Findings — one per missing gate

Each missing gate is filed as its own deduped issue labelled `bash-syntax-audit`
plus one `severity:*`:

- **Missing `bash -n` syntax gate → `severity:high`.** Invalid bash reaching the
  default branch is the exact regression this audit prevents.
- **Missing `shellcheck` gate → `severity:medium`.** The lint gate; error-level
  findings block at rollout, warnings are tightened later.
- **A main language missing its native validity check → `severity:high`.**
  Mirrors the best-practices compile-gate severity.

Every finding **leads with the fix**: name the missing gate and give the
concrete CI invocation to add so the regression class cannot recur. Each repo
commits its own gate — there is no shared cross-repo Action.

## Fail-loud contract

The detectors **never return a silent green on error**. A directory-walk or
file-read failure surfaces as a loud failure and is reported on this wrapper
issue — an audit that cannot complete is never reconciled as "no findings". A
gate whose status is *unknown* (no workflows loaded, or an unparseable workflow)
never produces a false "missing gate" finding.

## In-code suppression

A finding can be suppressed by adding a `best-practice-ignore: <finding-id>`
comment (the shared idle-task grammar) — for a gate finding, as a `#` comment in
a `.github/workflows/*` file. The audit skips a suppressed id on future runs.
