## Summary

A push made outside the worker (by hand, from a laptop, or from an interactive Claude Code session) no longer leaves the live PR description on the old summary. A new deferrable dispatch slot, Priority 1.64 **Reconcile PR Body Digests** (`worker/deno/lib/pr_body_reconcile.ts`), runs each cycle. It lists the open fleet-authored PRs in every monitored repo. For each body that carries both the worker marker and the `vibe-pr-summary sha256` digest marker, it reads `pr-summary-<N>.md` (or the legacy `docs/pr-summary-<N>.md`) and `pr-summary-<N>.facts.json` at the PR head through the contents API, with no checkout, and compares the digest. Only a mismatch rebuilds the body: the pass checks the head out into a disposable shallow clone and runs the existing `syncPrBodyFromSummary` there, so every carry-over rule and the head/ancestry guard apply unchanged. Steady state is silent: a match makes no edit and logs nothing, and it is memoised per head and digest for the life of the process. Closes #3760.

## Evidence

Backend-only change; verified by unit tests.

- The contents read is `gh api repos/{repo}/contents/<path>?ref=<head> -H "Accept: application/vnd.github.raw"`. A missing file answers `gh: Not Found (HTTP 404)` (the shape `isNotFound` matches), and every other failure is reported as a read failure. `worker/deno/tests/pr_body_reconcile_test.ts::headSummaryDigest - reads the summary and facts as raw content at the ref and returns a digest result` pins the argv.
- The rebuild runs the real `syncPrBodyFromSummary` against a real git checkout in `worker/deno/tests/pr_body_reconcile_test.ts::reconcile - end to end: mismatch rebuilds through the real sync with the new digest`, which asserts exactly one `gh pr edit` whose body carries the new digest marker.
- `issueNumberFromMarker` in `worker/deno/lib/pr_body_sync.ts` is now exported for the pass; its behaviour is unchanged.
- `checkedGit` in `worker/deno/lib/pr_body_reconcile.ts` is exported so its `Result` shape can be pinned directly. Through `disposableHeadCheckout`, whose callers only test `!step.ok`, a result missing `ok` reads the same as `ok: false`.
